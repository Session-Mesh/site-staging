# All your sessions on one screen

Who is working, who waits for you, and the last prompt each one received: the sidebar answers before you open anything.

Sessions that need you come first: Waiting for you when an agent asks a question or a permission, Finished, unread until you open it, Active while it works. Claude Code reports when it waits for you; the other agents show working or idle. The machine's other terminals are listed below them.

ProjectsYour sessions are one view. Projects, the other tab of the sidebar, is another: each project with its repository, its plan and its work. Read about Projects →

Tidy, and easy to find again

File sessions into folders and pin the ones that matter: a pinned conversation stays at hand even after it ends. Closed sessions are not lost: search past conversations by title or by their full text, and resume one in a click. The search runs on your machine; nothing is sent anywhere.

Terminals as they are

A terminal shows exactly what the program prints, so full-screen agent interfaces look as they do in your own terminal. Your agents keep your own subscription or API keys: session-mesh is just a terminal, a better one. Sessions survive a restart of the web server. After a restart of the machine, the page restores them: each agent resumes its conversation, and messages between agents are kept. You can open up to three columns.

Documents beside the terminals

A column can show HTML, Markdown with diagrams, PDF, images or source code. Click a path in a terminal, or run mesh-open FILE: an agent can show you the report it has just written. Documents beside the terminals are Linux-only for now: on macOS, mesh-open and a click on a path open nothing.

On your phone

One column, the session list as a drawer, and a key bar with Esc, Tab, Ctrl and arrows. Optional push notifications tell you when an agent finishes or waits for you.

Quick to drive

Ctrl/⌘+K finds a session, Ctrl/⌘+Shift+K works even inside a terminal, and ? lists the shortcuts. The interface is in English and French.

# Agents from different families, working together

On their own, Claude Code, Codex, Gemini CLI and the others do not talk to each other. In session-mesh they do: an agent leaves a message or a task for another, whoever made it, and you decide what gets read.

It works through mesh-board, an MCP server that session-mesh gives to the agents it starts. With it, an agent lists the other agents, writes to one of them and replies to what it received.

Agents that use session-mesh for you

Agents started in session-mesh know how to use it. They open a document beside their terminal to show you a report, start a session to hand off a task, draw on the whiteboard and update the projects they work on. All of it happens in plain sight, in the page.

You stay in charge

Before an agent reads a message, the page asks you. The text of a message is never typed into a terminal. An agent can also ask to start a new session or to restart its own conversation: nothing happens until you say yes.

A whiteboard you share with your agent

Each session has an Excalidraw whiteboard. You sketch, the agent reads your sketch and draws back on the same board, and every save keeps a revision. Watch an agent edit one →

Any program, eight agents built in

Any terminal program runs in session-mesh. Claude Code, Codex, Pi, OpenCode, Gemini CLI, Antigravity, Copilot CLI and Mistral Vibe are built in: you start them from the “New session” dialog, and they get the messaging tools.

# Structure for agent work

in progress Agents do better work with structure: a project they belong to, a plan to follow, a specification to check against.

The sidebar groups live sessions by the directory they work in, under “Observed directories”. A session whose directory could not be read is counted apart, never filed under a guessed project.

Roster first

Roster is the spec-driven harness session-mesh itself is written with: a task becomes a brief that a human validates, then a specification, a plan, an implementation, a review and quality checks before it ships. It is the first harness session-mesh reads.

Projects keeps each project with its folders, repository and sources, reads its Git repository and the tasks of its Roster roadmap, and shows them as a board, a dependency graph or a Gantt chart. Agents read and update the projects they work on.

Other harnesses next

The roadmap adds connectors for other families of agent harnesses, so that Projects reads their plans and tasks as it reads Roster's.

# Projects: the context of your work

Sessions show what runs now. Projects, the other tab of the sidebar, shows what the work belongs to: each project, its repository, its plan and the work to do.

  1. A project needs only a name. Add its folders, its repository and links to its sources when you need them. They stay on your machine.
  2. Seven views. Overview, Work, Roster, Repository, Sessions, Activity and Sources: the README and Git state, the roadmaps, the sessions that take part and what changed, refreshed when you ask.
  3. The work, three ways. A Kanban board (To do, In progress, Blocked, Done) with prerequisites and assignments, a dependency graph, and a Gantt chart of the recorded attempts. What is unknown is shown as unknown.
  4. The plan and the issues. The documents of a Roster roadmap open in a reader, and the project's GitHub or GitLab issues are listed with its work, read-only.
  5. Sessions stay where they are. Going to Projects and back keeps your terminals, drafts and columns as you left them.

Agents read and update the projects they work on. session-mesh writes nothing to GitHub or GitLab.

# Security, by design

session-mesh runs your terminals and your agents, so it is built to stay in your hands: local by default, documents kept apart from your sessions, and agent actions that wait for your approval.

  1. Local only, unless you choose otherwise. The server listens on 127.0.0.1 and refuses any other address at startup unless you allow it explicitly. To reach it from your other devices, you publish it on a private network of your choice; the installer can do it with Tailscale. A guide also covers HTTPS on a VPN address through a Caddy reverse proxy, with the server still on the loopback.
  2. A secret token to log in. The server creates it on first start, and only your user can read it.
  3. Documents cannot touch your sessions. A page written by an agent cannot read your login cookie, drive your terminals or call session-mesh's API. It opens in a sandbox that the browser treats as a separate site, under a restrictive Content Security Policy.
  4. Agent actions wait for your approval. Reading a message from another agent, starting a new session and restarting an agent's own conversation happen only after you approve them in the page.

The security policy gives the details: what session-mesh defends against, its known limits, and how to report a vulnerability privately.

# Install

alpha · Linux, macOS Built for one person on one machine, self-hosted and open source. Take part in its development and help shape where it goes.

in progress A ready-made package for Linux and macOS, installed with one script, with nothing to build.

  • Linux on x86_64: the primary platform.
  • macOS on Apple silicon: best-effort for now; a few features are Linux-only. Documents beside the terminals are not available there yet.

Until then, the source code and its documentation are on GitHub.

Download the installer of the release and its checksums, check them, and run it:

tag=v0.1.0
base="https://github.com/Session-Mesh/session-mesh/releases/download/$tag"
curl -fsSLO "$base/install.sh" -O "$base/SHA256SUMS"
sha256sum -c --ignore-missing SHA256SUMS   # macOS: shasum -a 256 -c --ignore-missing SHA256SUMS
bash install.sh

The same install.sh upgrades (--upgrade), goes back to the previous release (--rollback) and uninstalls (--uninstall). Verifying the download, and other ways to install.

It also runs on a server without a screen, such as your own VPS: reach it through an SSH tunnel or your private network. Use a machine that only you log in to.

release

v0.1.1 — patch release

A patch release of the 0.1 line: fixes, a native mesh-logout-all, and documentation.

  • Idle Claude Code and Codex sessions are no longer listed as working in the sidebar; a question or permission prompt is still always shown.
  • Clicks reach full-screen programs such as Claude Code that ignore a click right after a focus-in, on desktop and on a phone.
  • In Projects on a phone, the Kanban, Gantt and dependency views scroll sideways by touch, and the Kanban becomes vertical sections at 640 px or less.
  • mesh-logout-all is now a native program that needs no Python interpreter and ships with every release and install mode, including an upgrade from 0.1.0.
  • The bootstrap script installs the OCaml dependencies from the pinned opam repository, so it no longer fails on a host whose repository is older.
  • On macOS, the Configuration dialog reports the PTY host as running, as on Linux, and the local test and copyright scripts run there.

  • Linux first, and macOS 12.3 or later on Apple silicon, supported on a best-effort basis; on macOS, documents beside the terminals are not available yet.
